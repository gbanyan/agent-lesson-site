question: 讀取和修改有什麼不同？
answer: 讀取是取得資訊；修改會讓檔案或系統的狀態改變。
takeaway: 讀取讓 Agent 看見現況；修改會讓現況改變。審核動作時，別把兩者混在一起。
followUp: "處理＿＿＿＿以前，請把預計動作分成『只讀取』與『會修改』兩組。先完成只讀檢查，等我確認後再執行修改。"
newTerms: [Read, Write]
prerequisites: [B1]
visual: { type: concept, preset: read-write }
scenario:
  request: "讀一下 report.docx，告訴我第二章在說什麼；先不要修改。"
  actions:
    - "Agent 確認檔案存在與格式；對純文字可能直接讀取，對 DOCX 則可能執行 unzip、pandoc 或文件解析程式，把封裝內容轉成可讀文字。"
    - "它搜尋或整理抽出的段落，再根據第二章內容回答。"
    - "若你接著要求改字，Agent 可能要建立新文件、重新封裝 DOCX，或透過文件工具寫回；這一步才會改變檔案。"
  result: "只讀階段應回傳摘要而不改原檔；寫入階段則應列出改過的檔案與內容。"
  boundary: "『讀取』描述的是目的，不保證只會出現一條 read 指令。解析 PDF、DOCX、圖片或音訊時，Agent 可能執行數個程式並建立暫存檔；還要確認暫存位置、是否會上網，以及原檔不會被覆蓋。"
notTeach: [檔案權限位元, 系統呼叫]
---
兩者都可能是工作需要，但影響不同。單純打開純文字檔看一眼，和用文件編輯器或寫檔工具改內容，風險並不一樣。檔案格式也會改變做法：DOCX 裡其實打包了文字結構、格式和圖片，PDF 也不是一般純文字。為了讀懂它們，Agent 可能得呼叫解析程式、OCR 或轉檔工具。

判斷邊界時，除了「最後有沒有改原檔」，也要確認中間執行了哪些程式、建立了什麼暫存內容，以及資料有沒有送到外部服務。重要修改前，還應知道改的是什麼，以及是否有恢復方式。
